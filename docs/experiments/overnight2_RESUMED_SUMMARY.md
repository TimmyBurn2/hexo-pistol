## 3. WHAT THE ARC MEASURED THAT CHANGES A DECISION

**1. The sweep is 85.6% one thing.** Per tranche: capture 11 017 s of 12 870 s.
Play is 11%, replay 3%, the cold check 0.4%. **A lever not on the capture pass
cannot matter.**

**2. The capture searches every position 2.14 times, and that is structural.**
The pilot's own log reads `n 26  distinct-n 13  (13 duplicate games)` — exactly
2.0 at the game level, because `arena --capture` refuses a report whose two seats
do not attest one engine, so a self-match is the only capturable shape and one
deterministic engine plays each opening identically in both seats. With
cross-game transpositions: **742 records over 347 distinct positions**.

**A cache is sound and drops no record.** `capture::ask` sends `newgame` before
every ask and `new_game` calls `Searcher::clear`; the binary's own usage text
says *"no label is produced on a table another ask warmed"*. D-562(2) forbids
DROPPING a duplicate, not re-using an answer.

| | capture/tranche | 8-way wall | serial |
|---|---|---|---|
| registered | 11 017 s | **7.15 h** | 48.95 h |
| with the cache | 5 152 s | **3.89 h** | 22.89 h |

**3. An engine speedup is worth exactly `1/(1+g)` on ~97% of the sweep** — and
the cache is worth **+113.8% nps**. No micro-optimisation is worth a doubling.
**But `[profile.release]` sets `overflow-checks = true` and nothing else** — no
`lto`, no `codegen-units`, against Rust's defaults of `lto = false,
codegen-units = 16`. D-14 defers codegen tuning *"until there is a bench to judge
it by"*, and `tools/bench_delta.sh` now exists. The classic hazard is absent,
measured rather than assumed: `f32`/`f64` over core, eval, search and solver
returns **two hits, both in a cost-reporting binary**. Gain unknown; the bracket
is a pre-registration's to set.

**4. Concurrency cannot conflict, and the one finding is arithmetic.** `--out` is
claimed with `O_EXCL`; no temp files exist; 256 MiB TT per process peaks at 4 GiB
of 46 GB; one engine per tranche searches at a time so a tranche is ~1 core.
Every budget is a NODE budget, so load cannot change a label — the study
registers that as a criterion whose failure **stops the sweep, not the study**.
**Wall is `ceil(16/N)` waves, so N=12 is strictly no better than N=8**: only
`N ∈ {1,2,4,8,16}` balances at sixteen tranches, and if concurrency changes the
tranche count changes with it.

**5. The anchor's openings are not a refinement.** Game rule 3 forces the origin,
so v1 and v2 played **no opening at all** — and v2 measured the cost: **DISTINCT
GAMES 2 of 40**, on both seats. Its own reading: *"the interval's nominal N is 40
and its real one is 2."*

**6. The matchserver has no library target and no gate runs its Rust tests.**
No `src/lib.rs`; gate 3 is `cargo test --workspace` and the matchserver is a
detached workspace; gate 16 drives `run_match.sh`, which runs `cargo build` and
never `cargo test`. **Every obligation the anchor package takes on must be
discharged through the shipped script**, which is what `docs/process.md`'s
coverage rule asks for anyway.
