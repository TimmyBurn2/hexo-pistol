# Rule-9 justifications

CLAUDE.md rule 9 gives files a soft cap and asks a file over it to say WHY.
This is where that why lives, for every tracked `.rs` and `.sh` file over the
cap, and `tools/file_justification_check.sh` reads it — one home, so a
justification cannot drift from the gate that adjudicates it.

The texts came from the comment blocks that used to carry them, verbatim. Thirty
were recovered at `a14912a~1`, the revision before the header sweep
(docs/decisions.md D-443) deleted them along with the blocks they lived in; the
rest were moved out of the files that still carried them at the relocation, which
is where an entry written since then also comes from.

One entry per file, exactly:

    - `<tracked path>`: <why>

A why may not state a line count — rule 9 derives counts and never asserts
them. An entry naming a path that is not tracked, or one whose file is under
the cap, is a claim that does no work and the gate refuses it.

- `crates/pistol-arena/src/bin/stub_engine.rs`: every deviation this instrument makes lives in one file on purpose. Its whole value is that a reader can see the complete set of ways it differs from a real engine in one place, beside the real `Session` it otherwise serves through. Splitting the behaviour set from the code that acts on it would scatter exactly what a reviewer comes here to audit, and would let a mode exist that nothing acts on.
- `crates/pistol-arena/src/transcript.rs`: a parser's refusals and the record shapes they refuse against are one artefact. The field readers exist only to make the record readers refuse by name, and splitting them apart would put half of every refusal in another file — which is the arrangement that lets a shape drift away from the sentence that was supposed to guard it.
- `crates/pistol-arena/tests/replay_tests.rs`: the cases here are one run, seen four ways. They share a single harness — one arena run, one replay of it, one reader over the document that came back — and each case varies exactly one thing about that run: nothing (the clean pass), the worker count, the seat labels, or the engine's own demand to be told `newgame`. Splitting them would duplicate the harness into every piece, and a harness copied four ways is four things that can drift apart, which is the defect this whole work package exists to remove.
- `crates/pistol-arena/tests/capture_tests.rs`: one pass, seen every way it can go wrong. Every case here runs the SAME two-stage fixture — one self-play arena run, then one capture of the report it wrote — and varies exactly one thing about it: the engine's behaviour, the source report's budget kind, whether the two seats attest one engine, or which property of the written record is read back. Splitting them would copy that two-stage fixture into every piece, and the capture assertions are only worth anything BECAUSE the same generator produced the report they are taken from: a hand-written report would let the pass agree with a fixture rather than with the arena. The unit cases over the normalisation and the identity digest sit here rather than beside them because they are the same contract at a smaller grain — what a captured line keeps and what makes two captures the same run — and a reader checking whether the integration cases are vacuous needs to see both in one place.
- `crates/pistol-arena/src/labels_file.rs`: one grammar, stated once. The record type, the renderer that writes it and the loader that refuses everything the renderer cannot have produced are three views of a SINGLE format, and every refusal in the loader is only correct because of the column the renderer wrote — the key shapes, the three score kinds, the four token sets, the sentinel exemption. Splitting the reader from the writer would put a format's guarantee in one file and its enforcement in another, which is the seam this crate's own report reader was bitten at.
- `crates/pistol-arena/src/labels.rs`: one record's meaning, decided in one pass over one source line. Every column of a corpus record is derived here from the SAME two inputs — the capture record and the game the report holds for it — and the derivations are not independent: the replay that supplies `to_move` is the replay that supplies both position keys and the stones the third is folded from, and the word list the score is read out of is the word list the two node counters and the depth are read out of. A split would hand one half of that walk to another file and force the state across the boundary, which is the arrangement where a column comes to be derived from a position other than the one the label was asked at. The two guards that refuse a record before it is written sit beside the derivations they guard, because each names the column it refuses for and a guard that cannot name its column is a guard a reader cannot check.
- `crates/pistol-arena/tests/labels_tests.rs`: one transform, seen every way it can go wrong. Every case runs the SAME three-stage fixture — an arena self-play run, a capture of the report it wrote, then the transform over both — and varies exactly one thing: a column's derivation, a loader refusal, the binding between capture and report, or the book boundary. Splitting them would copy that three-stage fixture into every piece, and the column assertions are only worth anything BECAUSE the capture they read was produced by the arena rather than written by hand: a hand-written capture would let the transform agree with a fixture instead of with the engine.

- `crates/pistol-arena/src/exchange.rs`: one protocol conversation, and every way it can fail to be one. The ask, the answer and the refusals are a single exchange with a single engine, and each refusal is only correct because of the line the ask sent — the budget token it spelled, the position it named, the node count it asked to be held to. Splitting the refusals from the ask would put half of every failure's reason in another file, and the VOID class in particular is a judgement about an answer that only the ask's own budget makes readable.
- `tools/sealbot/matchserver/src/openings.rs`: a book's refusals ARE the reader. Eleven of them decide whether a file is a fixture, and each is only correct in the order the others run — the digest before the body, the body before the turns, the turns before the symmetry fold, the fold before the window is cut — because a later check reading a file an earlier one would have refused is a check on something that is not the book. Splitting the parse from the refusals would hand one half of that order to another file and make the sequence a convention rather than a shape a reader can see. This file exists at all because the option matrix chose a reader here over a dependency on `pistol-arena` (docs/experiments/matrix_anchor_openings_reader.md §4), and its cost was stated there.
- `tools/cold_label_check.py`: the external referent and the claim it is a referent FOR are one argument. The normalisation is re-derived here precisely so that it shares nothing with `capture::normalise`, and the sampling, the one-process-per-position ask and the byte comparison are three halves of a single claim — that a warm capture's answer equals a fresh process's. A split would put that independence across a file boundary, where a later edit routing both sides through one helper would retire the whole point without looking like it had.
- `tools/puzzle_corpus/extract.py`: the WP-P1 dispatch pins the extractor to one script, and the fetch, the parse and the V-checks share the record shape they build and annotate; splitting them would put that shape in a fourth file read by three.
- `tools/puzzle_corpus/mapping_gate.py`: two legs answered separately because they fail for different reasons, over ONE extracted corpus read through one set of symmetry and turn-grouping primitives. The gate's whole value is that a reader can see neither leg was chosen after seeing the other's answer; splitting them is what would let a mapping be selected by trying variants in one file and reported as a verdict in another.
- `tools/stage3_call_budget_derive.py`: every quantity it prints is ONE fraction presented in a unit, and the direction of each count is a property of the single division that produces it. Its parser is independently written from its sibling's on purpose — that is the second instrument — so moving the parse out would tempt the two into sharing code, which is the one thing this pair may not do.
- `tools/stage3_census_rank.py`: the recall definition is the file's subject and every column, ranking and verdict is downstream of it. Revision 1 scored the defender direction and reported it as the gate's recall; keeping the two directions, the ranking that reads only one of them and the verdict in one place is what makes that substitution visible to a reader instead of invisible across an import.
- `tools/stage3_premise_derive.py`: the relation, the honest statement of what checking it against the record does and does not establish, and its inversion at the registered bounds are one argument that has to be read in order. The two input modes deliberately share a single arithmetic path; a split by mode would give them two, which is the drift the script exists to make impossible.
- `tools/texel/fit.py`: the closed-form solve, the constraint set that IS the schema, and the rounding refusals are one artefact: each refusal is correct only because of the constraint set the solve was taken under, and a constraint set that is not the schema is one that relies on a downstream refusal to be right. Splitting them would rebuild exactly the seam D-658 was written to close.
- `tools/texel/test_texel.py`: one suite over three shipped scripts, and its value is that each positive check sits beside the negative control that proves it is not vacuous. Splitting by script would separate a check from its control — the failure mode `tools/SHELL_CHECKLIST.md` item 10 names — and the cross-script checks, which drive the composition rather than any one script, would have no home at all.
- `tools/wp15b_attribution_check.py`: one instrument, one file. A pre-registration names it WITH ITS REVISION, so every link of the criterion and every refusal that guards it is one argument a reader must be able to read whole before deciding that a governed run was a measurement. A split would put half of a refusal in another file, and the reader deciding that question would have to reconstruct it.
- `tools/wp16_warm_attribution_check.py`: one instrument, one file. Every link of this criterion, every refusal that guards it, and the proof clause (b) rests on are one argument, and a reader deciding whether a governed run is a measurement must be able to read the whole of it in one place. Splitting it would put half of a refusal in another file.
- `tools/wp21_assemble.py`: the raw manifest and the deduped manifest are two views of ONE pass over the same corpora, and the deduped one is an INDEX into the raw rather than a copy of it. Splitting the two writers is what would let the index name a row the manifest never recorded, which is the only way this pair can be wrong.
- `tools/wp21_tranche_config.py`: this file exists so that sixteen near-identical committed documents are generated rather than hand-copied. The registered value list and the writer that spends it are one thing; splitting them would restore by the back door the duplication the script was written to remove.
- `tools/determinism.sh`: one law, four runs, two comparisons, per seat — and the comparisons are not independent of the seat table they are taken over. A vs B is the gate proper and the per-position pass is what stops a session's own state answering for a fresh process, so splitting the driver from the comparator would put half of rule 4's executable form in another file, with the seat list readable from neither. It went over the cap when item 12 gave it a void class and a preflight over both filesystems, which is length the checklist asks for rather than length that accumulated.
